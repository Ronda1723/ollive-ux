From agent behavior testing to organizational compliance: layers, loops, and the report that survives a stranger's scrutiny.
The claimwhat the product asserts, before and after
v1 claims
"This agent behaves correctly."

Verified by adversarial test attempts against the agent. True even when the org around the agent has no DLP policy, no access controls, no incident plan.

v2 claims
"This organization is compliant."

A larger claim that behavior tests alone cannot support. Requires evidence of organizational practice plus tested agent behavior — each verified by the method that fits it.

Acceptance bar: the report holds up when a customer's customer questions it — a reader with no trust in Ollive, only in the evidence chain.
The compliance modelone framework decomposes into directives; each directive has exactly one verification method
Org directivesORG-* Organizational practices: encryption standards, DLP, access permissions, retention, contingency and incident plans. Cannot be tested by prompting an agent — they exist as policy and process. Verified byDocument evidence — uploaded, reviewed, versioned, expiring. No document, no score.
Agent directivesAGT-* Behavioral rules for the agent: discloses AI on ask, gates PHI behind identity, refuses clinical advice, escalates controlled-substance requests. Testable per rule. Verified byPro / anti behavior test cases — does required X, refuses prohibited Y. Ollive-curated, replayable.
Model-leveltabled Prescriptions about the underlying model. Not a scored category in v2; surfaces as general findings where relevant. Verified by—
The taxonomy is versioned and Ollive-defined — no industry standard exists. New buckets require explicit justification. Every framework mapping (EU AI Act, NIST AI RMF, ISO/IEC 42001, HIPAA) inherits it, so classification errors propagate; see stress points below.

Score rollupthe anti-black-box rule: every number expands to its evidence
framework  EU AI Act — completion 61% · org 14/23 verified · agent 21/28 passing
└ directive  Art. 13 → AGT-104 "agent discloses AI on ask" passing
  └ tests  6 scenarios · pro 4 / anti 2 · pack v3.2 pinned
    └ attempts  18 attempts · 17 pass · 1 indeterminate → adjudication
└ directive  Art. 10 → ORG-031 "data governance policy" awaiting evidence · caps completion until verified
A directive is passing when all its test cases pass on the latest run, or verified when its evidence is reviewed and unexpired. A framework is complete only when every applicable directive is one of the two. Eval selection is Ollive-curated — customizable eval sets would make the report's claims non-standard and indefensible to a third party.

The skeptic's journeythe customer's customer — the report's real acceptance test
1Opens the report cold. Reads scope first: which frameworks, which agents, which dates, what was excluded. Exclusions are stated, not discovered. 2Checks the method: taxonomy version, pack versions, judge calibration, review process for evidence. All pinned and cited inline. 3Picks any claim. An org claim resolves to a reviewed document — hash, reviewer, review date, expiry. An agent claim resolves to replayable test attempts — scenario IDs, seeds, transcripts. 4Looks for the gap: an agent claim presented as an org claim, or a questionnaire answer presented as evidence. The layer split exists so this search comes up empty.
Design consequence: the report never says "compliant" where it means "agent passed behavior tests." Layer labels appear on every claim.
Taxonomy stress pointswhere org/agent gets ambiguous when mapped to real frameworks — the load-bearing risk
Human oversightEU AI Act Art. 14 Requires both an org process (named humans, authority to intervene) and agent behavior (escalates, defers). One requirement, two verification methods. Resolution ruleSplit into two linked directives — ORG half and AGT half — never a third bucket.
Logging & traceabilityArt. 12 · NIST MAP/MEASURE Neither a policy document nor promptable behavior — it's a platform capability. Verifying it means introspecting the integration, a third verification method entering quietly. Resolution ruleTreat as org directive with system evidence (config export, log sample) instead of policy PDF — evidence types expand, buckets don't.
Retention & deletionHIPAA · GDPR Art. 17 Policy says 30 days (org, documented); the agent tells callers "we delete recordings" (agent, testable). The two can verify independently and still contradict each other. Resolution ruleCross-layer consistency check: linked directives must agree or both flag.
Accuracy & robustnessArt. 15 Looks agent-testable, but a sample-based pass rate is a statistical estimate, not a binary directive state. "Passing at 94% ±3" is not "complies." Resolution ruleDirectives with statistical verdicts carry thresholds and intervals in the report — never collapsed to a checkmark.
Incident responseNIST MANAGE · HIPAA §164.308 A contingency plan PDF proves the process exists. Only the monitoring config — alert routes wired, on-call set — proves it operates. Resolution ruleEvidence tiers: documented vs operating. The report shows which tier was verified.
