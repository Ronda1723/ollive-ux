TypeGeist only — Geist Mono for data
T1Geist for every heading, label and body. Page title 24/600 tight (-.02em) · section title 14/600 · body 13.5–14/400 · captions 12.5 muted.
T2Geist Mono is the data voice: scores, counts, dates, timestamps, TEC codes, IDs. If a value could appear in a CSV, it's mono.
T3One uppercase style only: 11/600, letter-spacing .08em, muted — used for table headers, stat labels and section eyebrows. Nothing else is uppercase.

Behavior rulesthe fixes over the current app
B1Never leak internals: OUTPUT_RELIABILITY_AND_ACCURACY renders as "Output reliability & accuracy". UUIDs and TEC codes live on a mono second line, truncated, never in titles.
B2Dashboard reflects reality — stats derive from the same data as the Agents page. Locked modules explain exactly what unlocks them and show progress.
B3Status is a pill, severity is a color, and they never disagree. "At risk" with a high score explains itself (open high-severity issue blocks deployment).
B4Every empty state says what the space is for and offers the one action that fills it.
B5Detail lives in a right drawer (560px) opened from rows — verdict first, then metric, judge reasoning, transcript. Esc or scrim closes.
B6Issues are work, not facts. Every issue has severity, state (Open → Fixing → Verify → Resolved / Risk accepted), an owner, a root cause, a suggested fix (diff), and a targeted "Verify fix" that re-runs only its failing scenarios. Risk acceptance requires sign-off and is audit-logged.
B7Every risk has a price. Issues carry expected-loss dollars (probability × severity from the disclosure profile), lists rank by exposure reduction, and the methodology is always one click away. Money is always mono.
B8Scores bind to versions. Each run pins the agent version + prompt hash; if the deployed config differs from the assessed one, a staleness banner appears. Runs are diffable — newly-failing scenarios surface first.
B9Trust is outward-facing. The trust page is shareable, read-only, watermarked "Verified by Ollive", and derives from live platform data — the customer can't edit it, which is what makes it worth showing a buyer.
Eval integrity ruleswhat makes the score defensible
E1No number without an interval. Scores show 95% CIs (clustered by failure mode); run deltas use paired tests and are labelled significant or within noise — a noise delta is never celebrated.
E2Judges carry credentials. Every metric shows its judge-vs-human κ and label count; below κ 0.5 it's excluded from the score. High-severity verdicts use a vendor-diverse 3-judge panel with a consensus rule.
E3Indeterminate is a queue, not a bucket. Humans adjudicate splits at keyboard speed; labels become rubric guidance, judges recalibrate, queued attempts re-judge, and the κ + indeterminate-rate trends are shown.
E4Coverage is computed, not claimed. The taxonomy is versioned and mapped to OWASP/NIST; applicability derives from the agent's actual tools and data access; applicable-but-untested modes are a visible defect with one-click pack generation.
E5Personas are specified, reality is the referee. Every attempt records its caller persona and audio conditions (cooperative-only testing inflates scores); real production calls import as regression scenarios and the sim-to-real gap is tracked as the eval's own honesty metric.
E6Everything is pinned. Scenario packs, judge prompts, judge models and seeds are versioned per run — same agent + same pack ⇒ same result within the stated variance band.
